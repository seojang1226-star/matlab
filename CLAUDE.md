# CLAUDE.md - AI Assistant Guide for MATLAB Turbine Pre-Processing Tool

## Project Overview

This is a **MATLAB App Designer application** for automated CFD pre-processing of Doosan turbine components. The application automates geometry creation, mesh generation, and CFX setup for multi-stage turbine analysis including blades, interstage seals, and tip seals.

### Repository Information
- **Language**: MATLAB (App Designer)
- **Primary Application**: `multistage_pre.m` (15,306 lines)
- **Helper Functions**: `Result_File_Handler.m`
- **Domain**: CFD automation for turbine analysis
- **Target Software**: ANSYS CFX (versions 2022 R2 and later)

## Application Features

### Tab Structure

1. **Geometry Tab**
   - **Turbine Blade Sub-tab**: Blade geometry setup and mesh generation
   - **Interstage Seal Sub-tab**: Seal geometry and parameters (15 seal types)
   - **Tip Seal Sub-tab**: Tip seal configuration (6 types with size variations)

2. **CFX Pre Tab**
   - Pre-processing settings (RPM, pressures, temperatures, mass flow)
   - Extraction configurations
   - Heat balance file import
   - CFX-Pre automation

### Key Functionalities

1. **Geometry Processing**
   - Multi-stage turbine blade geometry import
   - HP (High Pressure) and IP (Intermediate Pressure) turbine support
   - Blade offset calculations (Plus/Minus directions)
   - Fillet parameters for rotor and stator blades

2. **Mesh Generation**
   - Automated ANSYS TurboGrid mesh creation
   - Blade-only or full stage meshing options
   - Journal file generation for automation

3. **Seal Handling**
   - **Interstage Seals**: 15 different seal types with parametric tables
   - **Tip Seals**: 6 base types with size variations
   - Dynamic parameter tables based on seal type selection
   - Image previews for each seal configuration

4. **CFX Pre-Processing**
   - Boundary condition setup
   - Inlet/outlet conditions (pressure, temperature, enthalpy)
   - Extraction mass flow and temperature settings
   - RPM configuration
   - Automated CFX-Pre script generation

## Development Conventions

### Code Style

1. **Naming Conventions**
   - UI Components: PascalCase with descriptive suffixes
     - Buttons: `*_Button` (e.g., `File_Open_Button`)
     - Text Areas: `*_TextArea` (e.g., `Project_Name_TextArea`)
     - Dropdowns: `*_DropDown` (e.g., `CFX_Version_DropDown`)
     - Tables: `*_Table` (e.g., `Stage_Table`)
     - Panels: `*_Panel` (e.g., `Stage_Table_Panel`)

2. **Private Properties**
   - Snake_case for data properties (e.g., `sort_parameter_table`, `tip_blade_extend_In`)
   - camelCase for some properties (e.g., `isCanceled`, `TableCounter`)
   - Array properties for seal types: `type1` through `type15`
   - Matches arrays: `matches_1` through `matches_8`, plus `matches_1_hp`, `matches_2_hp`, `matches_3_hp`

3. **Comments**
   - Auto-generated App Designer comments in English
   - Some domain-specific comments in Korean (e.g., line 1064: "환경변수 설정" - Environment variable settings)
   - Function headers indicate callback type and associated UI component

### Refactoring Patterns

**When updating similar components, use loops instead of repetition:**

Good (Current Pattern):
```matlab
dropdownNames = {'Component_1', 'Component_2', 'Component_3'};
for i = 1:length(dropdownNames)
    app.(dropdownNames{i}).Property = value;
end
```

Bad (Avoid):
```matlab
app.Component_1.Property = value;
app.Component_2.Property = value;
app.Component_3.Property = value;
```

- **No subdirectories**: Keep all `.m` files at root level
- **Naming convention for new files**: Use descriptive names with underscore separators (e.g., `Result_File_Handler.m`)

## Common Modification Scenarios

### Adding a New UI Component

1. **Use App Designer GUI** to add component
2. **Component will auto-generate** in properties section

### Updating Dropdown Logic

1. **Read the component structure** first
2. **Identify all similar components** that need updating
3. **Use loop pattern** for bulk updates (see Result_File_Handler.m:30-41)
4. **Test with actual data** before committing

### Modifying Seal Type Parameters

1. **Locate seal type arrays**: `app.type1` through `app.type15` (interstage) or `app.tip_type1` through `app.tip_type6` (tip)
2. **Update in callback functions**: `InterstageDropdownCallback` or `TipDropdownCallback`
3. **Maintain MAT parameter filtering** pattern:
   ```matlab
   matches_Name = Parameter_Type_Name(cellfun(@(x) contains(x, 'MAT'), Parameter_Type_Name));
   matches_Val = Parameter_Type_Val(cellfun(@(x) contains(x, 'MAT'), Parameter_Type_Name));
   app.matches_N = [matches_Name, matches_Val];
   ```

### Adding New Seal Types

1. **Add new type property** in private properties section (e.g., `type16`)
2. **Update dropdown items** in initialization
3. **Add image file** for visual reference
4. **Create parameter table** structure
5. **Update callback logic** to handle new type
6. **Add matching logic** if MAT parameters needed

2. **Preserve auto-generated comments** from App Designer
